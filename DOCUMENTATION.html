Project Plan & Academic Cloud Deployment Constraints

The system is a web-based recruitment platform connecting Employers with Job Seekers. It enforces role-based permissions, persistent server sessions, and rigorous backend ownership checks.

🚫
STRICT COURSE BOUNDARIES — PROHIBITED TECHNOLOGIES

To maintain academic alignment with WEB II curriculum standards, the following are strictly prohibited: NO JWT • NO Passport.js • NO Redux / Zustand • NO TypeScript • NO Multer / File Upload Storage • NO GraphQL • NO WebSockets • NO Admin Roles.

Software Requirements Specification (SRS)

The system strictly contains three user states. There is no Admin role.

1. Guest Scope
  • Browse open jobs with pagination.
  • Keyword search (title, company, location, description).
  • Filter by Category, Type, and Salary range.
  • Sort by Newest, Oldest, Highest/Lowest Salary.
  • View detailed job requirements.
  • Register as Seeker or Employer / Log in.
2. Job Seeker Scope
  • Log in securely with session cookie.
  • Apply for jobs with coverLetter & resumeLink.
  • Atomic duplicate prevention (1 application per job).
  • Track all applied jobs and status in real-time.
  • Personal Seeker Dashboard with metric counts.
  • Manage profile name and update password.
3. Employer Scope
  • Register with company name and log in.
  • Create, edit, close, and delete job postings.
  • Strict ownership check: mutate only owned jobs.
  • Review candidate applications and open resume links.
  • Update application status (state-machine transition).
  • Employer Dashboard with aggregate recruitment analytics.
📋
EXPLICIT SCOPE EXCLUSIONS (PREVENTING SCOPE CREEP)

No payment processing, no resume file upload storage (Multer), no real-time messaging, no automated email delivery (Nodemailer), and no AI resume screening algorithms. Focus remains 100% on core WEB II competencies.

Cross-Origin Cookies (Vercel to Render)

Because the frontend is hosted on Vercel and the API on Render, requests are cross-origin. The Express server and cookie engine must configure:

Production Cookie & CORS Configuration 
// server.js - Strict CORS
app.use(cors({
  origin: process.env.CLIENT_URL, // e.g. https://jobboard.vercel.app
  credentials: true                // MANDATORY: Allows cookie transmission
}));

// server/utils/session.js - Cookie Attributes
const isProduction = process.env.NODE_ENV === 'production';
const cookieOptions = {
  httpOnly: true,
  sameSite: isProduction ? 'none' : 'lax', // 'none' required for cross-domain Vercel -> Render
  secure: isProduction ? true : false,     // HTTPS required when sameSite is 'none'
  maxAge: 7 * 24 * 60 * 60 * 1000          // 7 days
};

Database Design & Entity-Relationship Modeling

Entity-Relationship Diagram (ERD)

Critical Indexes & Constraints

1. User Email Uniqueness

userSchema.index({ email: 1 }, { unique: true })

Guarantees unique account credentials across all registrations. Duplicate registration returns 409 Conflict.

2. Compound Unique Index (Applications)

applicationSchema.index({ job: 1, applicant: 1 }, { unique: true })

Guarantees at the database engine level that a seeker cannot submit multiple applications to the same job posting.

3. MongoDB TTL Auto-Purge (Sessions)

sessionSchema.index({ expiresAt: 1 }, { expireAfterSeconds: 0 })

MongoDB automatically deletes expired session documents in the background once expiresAt is reached.

REST API Specification & Express Route Ordering

⚠️
CRITICAL ROUTE ORDERING REQUIREMENT IN EXPRESS

In server/routes/jobs.js, router.get('/mine', ...) MUST be registered BEFORE router.get('/:id', ...). Otherwise Express will treat the literal string "mine" as an :id parameter and crash on an invalid MongoDB ObjectId lookup!

Authentication & Cookie Security Engine

Authentication uses stateful server sessions stored in MongoDB and linked via an httpOnly cookie. Passwords are hashed with bcrypt (10 salt rounds).

server/middleware/auth.js (requireAuth & requireRole) 
const Session = require('../models/Session');
const User = require('../models/User');

const requireAuth = async (req, res, next) => {
  try {
    const sessionId = req.cookies.sessionId;
    if (!sessionId) {
      return res.status(401).json({ message: 'Authentication required. Please log in.' });
    }

    const session = await Session.findOne({ sessionId });
    if (!session || new Date() > session.expiresAt) {
      res.clearCookie('sessionId');
      return res.status(401).json({ message: 'Session expired. Please log in again.' });
    }

    const user = await User.findById(session.user).select('-passwordHash');
    if (!user) {
      res.clearCookie('sessionId');
      return res.status(401).json({ message: 'User account not found.' });
    }

    req.user = user;
    req.session = session;
    next();
  } catch (err) {
    next(err);
  }
};

const requireRole = (...roles) => (req, res, next) => {
  if (!req.user || !roles.includes(req.user.role)) {
    return res.status(403).json({ message: `Forbidden. Requires role: [${roles.join(', ')}]` });
  }
  next();
};

module.exports = { requireAuth, requireRole };

Business Rules Specification (BR-001 through BR-010)

Rule ID Rule Name Trigger Condition Enforced Outcome & HTTP Status
BR-001 Unique Email User registers with existing email Reject with 409 Conflict
BR-002 Duplicate Application Prevention Seeker applies twice to same job Reject with 409 Conflict
BR-003 Closed Job Freeze Seeker applies to a CLOSED job Reject with 400 Bad Request (Job remains viewable)
BR-004 Job Ownership Check Employer mutates job they do not own Reject with 403 Forbidden
BR-005 Status State-Machine Modifying ACCEPTED or REJECTED application Reject with 400 Bad Request (Terminal states)
BR-006 Role Segregation Seeker creates job / Employer applies Reject with 403 Forbidden
BR-007 Mandatory Application Fields Missing cover letter (<20 chars) or invalid URL Reject with 400 Bad Request
BR-008 Route Ordering Declaring /:id before /mine Strict code rule: declare /mine first
BR-009 Cascade Deletion Employer deletes job posting Prune all associated application documents
BR-010 Session Invalidation User logs out Delete Session in DB & clear cookie
BR-011 Application Withdrawal Candidate withdraws an application Allowed only if status is PENDING; terminal states blocked (400 Bad Request)

UI/UX & Component Design

The client is a responsive React Single Page Application styled with Vanilla CSS custom properties.

client/src/context/AuthContext.jsx 
import React, { createContext, useContext, useState, useEffect } from 'react';
import api from '../services/api';

const AuthContext = createContext(null);

export const AuthProvider = ({ children }) => {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  const checkAuth = async () => {
    try {
      const res = await api.get('/auth/me');
      setUser(res.data.user);
    } catch {
      setUser(null);
    } finally {
      setLoading(false);
    }
  };

  useEffect(() => { checkAuth(); }, []);

  const login = async (creds) => {
    const res = await api.post('/auth/login', creds);
    setUser(res.data.user);
    return res.data;
  };

  const logout = async () => {
    try { await api.post('/auth/logout'); }
    finally { setUser(null); }
  };

  return (
    
      {children}
    
  );
};

export const useAuth = () => useContext(AuthContext);
